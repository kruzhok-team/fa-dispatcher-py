# Спецификация интерфейса диспетчера КА для Python

Версия документа: 0.1 (2026-10-28)

Документ предназначен авторам программ, исполняющих конечные автоматы на
диспетчере, и авторам диаграмм, которые эти программы исполняют. В нём
описано всё, чем они пользуются: диаграмма автомата, `Dispatcher`, автомат,
прочитанный из документа, классы символов, ленты и файлы тестов, командная
строка, ошибки и сессия, предоставляющая автомат редактору для пошагового
исполнения. Правила исполнения и их обоснование приведены в
`ARCHITECTURE.md`.

```
 программа                            fad                           диаграмма
 ─────────                            ───                           ─────────
 Dispatcher(source, trace)  ────────▶ автомат ◀────────── документ (CyberiadaML),
 start() feed() end() run()           таблица шагов        type/ fa, классы
 state() symbols() classify()             │
      ▲                                   │
      └── шаги, результаты, трассировка ◀─┘
 fad_tape: ленты, файлы тестов     fad_session: редактор     fa-run: командная строка
```

Всё импортируется из одного модуля: `import fad`; `fad_tape` и `fad_session`
импортируются отдельно.

## Соглашения

* **Символ** — строка: символ входного алфавита на переходе, символ
  выходного алфавита на выходе. Диспетчер сравнивает символы в том виде, в
  каком они записаны.
* **Лента** — последовательность символов. Диспетчер читает её по одному
  символу за шаг и после последнего посылает `EOF`.
* **Текст** — строка, символы которой становятся символами автомата через
  классы диаграммы (см. «Классы символов»).
* **Вердикт** прогона — `accepted` (лента допущена) или `rejected` (лента
  отвергнута). Прогон, не нашедший перехода по символу, сразу отвергает
  ленту и дальше её не читает.
* **Выход** — список выходных символов, записанных прогоном, в порядке
  записи.
* **Позиция** считает символы, прочитанные до неё, от 0. У `EOF` позиция
  конца ленты.
* Элементы называются идентификаторами документа: состояния,
  псевдосостояния и переходы.

## Диаграмма автомата

Диаграмма — документ CGML (ПНСТ 1044-2025) с одной машиной состояний и
параметром `type/ fa` в `CGML_META` (`FA-extension.md`, 5). Элементы:

| Элемент | В диаграмме | Пример |
|---|---|---|
| состояние | простое состояние; его выходной символ, если есть, — его `entry/` | `entry/` `1` |
| составное состояние | одна область, без `entry/`; начальное псевдосостояние внутри, когда переход ведёт в само составное состояние | |
| начальное псевдосостояние | одно на верхнем уровне; его переход без текста | |
| конечное состояние | на верхнем уровне, в него ведёт только `EOF` | |
| переход | входной символ или `EOF`, затем `/`, затем не более одного выходного символа | `1/`, `1/ 0`, `EOF/ ODD`, `J/ .---` |
| алфавиты | формальные комментарии `FA_INPUT` или `FA_INPUT_RE`, `FA_OUTPUT` или `FA_OUTPUT_RE` на верхнем уровне: символ или шаблон в строке | `FA_OUTPUT_RE`: `[A-Z]` |
| классы | формальный комментарий `CGML_COMPONENT <id>` с `type/ Classes` | см. «Классы символов» |

* Состояние, в которое привёл символ, записывает сначала выход перехода,
  затем свой выход.
* Символ читает переход активного состояния или, если его нет, ближайшего
  объемлющего состояния; внутренний переход по тому же символу замещает
  объемлющий.
* Состояние **допускающее**, если его переход по `EOF` или переход по `EOF`
  объемлющего состояния ведёт в конечное состояние.
* Символ не совпадает со служебными словами: `do`, `else`, `entry`, `exit`,
  `propagate`, `block`, `defer`, `ANY`, `UNKNOWN`, `EOF`.
* Входной символ имеет вид имени события: буквы, цифры и `_`, с пробелами и
  точками внутри (`DOOR_OPEN`, `0`, `letter`). Остальные символы попадают в
  автомат через классы.
* Выходной символ — одна строка: `ODD`, `.---`, `/`. libcyberiadaml (1.1.0)
  отвергает символ вида «имя события и косая черта» (`c/`): так она читает
  второй блок события.

Библиотека проверяет эти правила при открытии документа; неверный документ
вызывает `DocumentError`.

## Диспетчер

```python
import fad

dispatcher = fad.Dispatcher('parity-mealy.graphml')
result = dispatcher.run(['1', '0', '1', '1'])
print(result.verdict, result.output)          # accepted ['ODD']

dispatcher.start()                            # по шагам
for symbol in dispatcher.classify('1011'):
    step = dispatcher.feed(symbol)
    if dispatcher.verdict:                    # отвергнута
        break
else:
    step = dispatcher.end()
print(dispatcher.verdict, dispatcher.output)
```

### `Dispatcher(source, trace=None)`

| Параметр | Значение |
|---|---|
| `source` | путь к документу CyberiadaML или `fad.Automaton` |
| `trace` | функция, вызываемая с каждой записью трассировки (кортежем); без неё трассировки нет |

Конструктор читает документ и вычисляет таблицу шагов; ошибка —
`DocumentError`. До `start()` или `run()` ничего не исполняется.

### Члены

| Член | Возвращает | Делает |
|---|---|---|
| `start()` | `Step` начала | начинает новый прогон: проходит начальные переходы до простого состояния и записывает его выход |
| `feed(symbol)` | `Step` | читает один символ; без перехода лента отвергнута; `feed(fad.EOF)` — это `end()` |
| `end()` | `Step` символа `EOF` | заканчивает ленту: допущена, когда `EOF` приводит в конечное состояние, иначе отвергнута |
| `run(tape)` | `Result` | `start()`, `feed()` для каждого символа до отказа, `end()` |
| `classify(text)` | список символов | символы текста через классы |
| `state()` | идентификатор состояния | активное простое состояние; после вердикта — состояние, где прогон остановился |
| `states()` | список идентификаторов | активное состояние и объемлющие его составные, начиная с внешнего |
| `symbols()` | список символов | символы, которые читает активное состояние, сначала собственные, затем унаследованные, каждые в порядке документа, кроме `EOF` |
| `accepting()` | `bool` | допустил бы `end()` ленту сейчас |
| `position` | `int` | число прочитанных прогоном символов |
| `output` | список символов | выход прогона на данный момент |
| `verdict` | `fad.ACCEPTED`, `fad.REJECTED` или `None` | `None`, пока прогон идёт |
| `running` | `bool` | прогон начат и не имеет вердикта |
| `automaton` | `Automaton` | |

`feed()` и `end()` без идущего прогона — до `start()` или после вердикта —
вызывают `StoppedError`; `start()` начинает заново в любой момент.

### `Step` и `Result`

`Step`:

| Поле | Значение |
|---|---|
| `symbol` | символ; `None` для начала, `fad.EOF` для конца |
| `position` | позиция символа |
| `status` | `fad.FIRED` или `fad.REJECTED`, когда ни один переход не читает символ |
| `transition` | идентификатор перехода, `None` для начала и отказа |
| `exited`, `entered` | идентификаторы покинутых и введённых состояний, по порядку |
| `output` | выходные символы шага: ни одного, один или два |
| `fired` | идентификаторы для редактора: переход, пройденные начальные псевдосостояния и их переходы |
| `reason` | почему символ отвергнут: `R has no DASH` |
| `verdict` | вердикт, если его дал этот шаг, иначе `None` |

`Result`: `verdict`, `output`, `position` (число прочитанных символов),
`state` (где прогон остановился), `reason`, `steps` (включая начало) и
`message`:

| Вердикт | `message` |
|---|---|
| допущена | `accepted` |
| символ без перехода | `rejected at 3: R has no DASH` |
| символ вне объявленного списка `FA_INPUT` | `rejected at 2: 2 is not in FA_INPUT` |
| `EOF` в недопускающем состоянии | `rejected at EOF: T1 is not accepting` |

Причины называют состояния по именам, а безымянные — по идентификаторам.

### Трассировка

Диспетчер вызывает функцию трассировки с записью — кортежем, первый элемент
которого вид записи:

| Запись | Когда |
|---|---|
| `('start', state)` | прогон начинается в простом состоянии |
| `('symbol', symbol, position)` | прочитан символ; также `EOF` |
| `('fire', transition)` | исполнен переход |
| `('exit', state)` | покинуто состояние |
| `('enter', state)` | введено состояние |
| `('output', symbol)` | записан выходной символ |
| `('rejected', position, reason)` | прогон остановлен |
| `('accepted',)` | `EOF` привёл в конечное состояние |

## Автомат

`fad.read(path)` читает документ в `Automaton`, который `Dispatcher`
принимает как источник; несколько диспетчеров разделяют один автомат.

| Член | Значение |
|---|---|
| `name` | имя машины состояний |
| `states` | словарь: идентификатор -> `State` с `id`, `name`, `parent` (идентификатор, `None` на верхнем уровне), `composite`, `output` (символ `entry/` или `None`) |
| `transitions` | список `Transition` с `id`, `source`, `target`, `symbol` (`None` для начального), `output` |
| `initial`, `final` | идентификаторы начального псевдосостояния верхнего уровня и конечного состояния |
| `input_alphabet`, `output_alphabet` | `(name, lines)` комментария алфавита или `None` |
| `classes` | список `(symbol, pattern)` в порядке документа |
| `accepting` | множество допускающих состояний |
| `edge(state, symbol)` | `Edge` шага или `None`: `transition`, `exited`, `entered`, `output`, `fired` |
| `symbols(state)` | символы, которые читает состояние, сначала собственные, затем унаследованные |
| `events()` | символы списка `FA_INPUT`, а без него — символы переходов |
| `classify(text)` | как `Dispatcher.classify()` |
| `label(id)` | имя элемента или его идентификатор |

## Классы символов

Текст попадает в автомат через компонент `Classes`, поэтому диаграмма читает
несколько символов вместо каждого знака:

```
CGML_COMPONENT chars
type/ Classes

letter/ [a-zA-Zа-яА-ЯёЁ]

digit/ [0-9]

dot/ \.

sep/ [_\-]

at/ @
```

* Каждый параметр `<symbol>/ <pattern>` — класс; `type` принадлежит
  компоненту. Параметры разделяются пустыми строками (ПНСТ 1044, 10.3.1).
* Шаблон соответствует одному знаку:

  | Шаблон | Соответствует |
  |---|---|
  | `a`, `@`, `я` | этому знаку |
  | `\.`, `\-`, `\\` | специальному знаку: `.` `[` `]` `-` `{` `}` `,` `?` `(` `)` `\|` `\` |
  | `.` | любому знаку |
  | `[a-z0-9_]`, `[ ]`, `[_\-]` | знаку множества: знаки, диапазоны `a-z`, экранированные специальные; `[ ]` — пробел |

* Знак становится символом первого подходящего класса в порядке документа
  или остаётся самим собой.
* Если объявлен список `FA_INPUT`, каждый символ класса входит в него
  (шаблоны `FA_INPUT_RE` не сопоставляются).
* В документе не больше одного компонента `Classes`; без него каждый знак —
  отдельный символ.
* Классы применяются только к текстам; лента символов читается как есть.

## Ленты и файлы тестов

`fad_tape` читает и записывает файлы лент и файлы тестов.

Файл ленты:

```
# лента декодера Морзе
DOT
DASH
".--- .-"
```

* Строка — символ: вся строка без окружающих пробелов; `#` начинает строку
  комментария; пустые строки пропускаются.
* Строка в двойных кавычках — текст: символ на каждый знак.

Файл тестов:

```
# + допущена, - отвергнута, => ожидаемый выход
+ 1 0 1 1 => ODD
+ => EVEN
- 1 1 1
- "j..doe@mail.ru"
+ "JA" => .--- .-
```

* Строка — лента: `+` или `-`, затем символы через пробел или один текст в
  двойных кавычках, затем, если нужно, `=>` и ожидаемый выход — символы
  через пробел. `+ => EVEN` — пустая лента; без `=>` выход не проверяется.
* Текст — знаки между первой и последней двойной кавычкой строки.
* Символ с пробелом внутри записывается только в файле ленты.

| Член | Значение |
|---|---|
| `read(text)` | элементы файла ленты: `Item` с `kind` (`'symbol'` или `'text'`), `value`, `line`; неверная строка — `TapeError` с `line` |
| `write(items)` | текст файла ленты |
| `symbols(items, classify)` | символы элементов; текст — через `classify` |
| `read_tests(text)` | тесты: `Test` с `line`, `verdict` (ожидаемым), `items`, `output` (список или `None`: не проверяется) |
| `check(dispatcher, tests)` | неудачи: `Failure` с `test`, `result`, `message` |

## Командная строка

```
fa-run DIAGRAM [SYMBOL ...]     лента символов
fa-run DIAGRAM --text TEXT      текст; "-" читает stdin без последнего перевода строки
fa-run DIAGRAM --tape FILE      файл ленты; "-" читает stdin
fa-run DIAGRAM --test FILE      файл тестов
fa-run DIAGRAM --session        сессия редактора через stdin и stdout
       --diagnostics FILE       с --test: неудачи как замечания редактора
       --join                   выход без пробелов между символами
       --trace                  записи трассировки в stderr
```

* В stdout выход одной строкой, символы через пробел (с `--join` — без
  пробелов); без выхода строка пустая. В stderr — `message` результата,
  поэтому один автомат передаёт выход другому:

  ```
  $ fa-run morse-encoder.graphml --text JA | fa-run morse-decoder.graphml --text - --join
  accepted
  accepted
  JA
  ```

* `--diagnostics` записывает неудачи `--test` как файл замечаний плагинов
  редактора: `error` на состоянии, где остановился прогон, на каждую
  непрошедшую строку, иначе один `info` с их числом.
* `--test` пишет в stderr строку на каждую неудачу,
  `email.tests:4: expected accepted, got rejected at 2: LocalSep has no dot`,
  а затем `7 passed` или `6 passed, 1 failed`.
* Код возврата 0, когда лента допущена или все тесты прошли, 1, когда она
  отвергнута или тест не прошёл, 2 — неверный документ, лента или файл
  тестов.

## Ошибки

| Ошибка | Когда |
|---|---|
| `fad.DocumentError` | документ не `type/ fa`, библиотека его отвергла (её сообщение), классы неверны; вызывается `read()` и конструктором |
| `fad.TapeError` | неверна строка файла ленты или файла тестов; `line` — её номер |
| `fad.StoppedError` | `feed()` или `end()` без идущего прогона |

Они подклассы `fad.FAError`.

## Сессии

`fad_session` предоставляет автомат редактору CyberiadaPro. Редактор
отмечает на диаграмме активное состояние и сработавший переход, а
пользователь проходит ленту по шагам, прогоняет её, вводит символы и
сохраняет прогон. Протокол — глава «Sessions» `PLUGIN-API.md` редактора;
это управляемая сессия (driven) с потоковой логикой (stream).

```
 CyberiadaPro               fad_session                     fad
 ────────────               ───────────                     ───
 control, event, ──stdin──▶ лента, позиция, ──────────────▶ Dispatcher:
 input, save                введённые символы               start() feed() end()
 отметки, история, ◀stdout─ state, history ◀──────── шаги   states() symbols()
 вердикт, выход
```

| Член | Значение |
|---|---|
| `serve(dispatcher, reader=sys.stdin, writer=sys.stdout)` | ведёт сессию до `shutdown` или конца ввода; возвращает код возврата 0 |

`fa-run DIAGRAM --session` предоставляет документ. Ответ на `initialize`:

```json
{"kind": "driven", "logic": "stream", "steps": ["input"],
 "controls": ["step", "run", "restart"], "events": ["DOT", "DASH", "GAP", "WORD"],
 "end": "EOF", "stream": true, "save": true, "verdict": true, "output": true}
```

`events` — `events()` автомата: символы списка `FA_INPUT` или символы
переходов.

| Единица, сообщение | Сессия делает |
|---|---|
| шаг `input` | следующий символ ленты, знак текста считается одним; после последнего — `end()`; после вердикта статус `finished` |
| `run` | шаги до вердикта; скорость не важна, часов нет |
| `restart` | `start()`; лента с первого символа |
| `event` | `feed(name)` или `end()` для `EOF`, с источником `user` |
| `input` | читает файл ленты и начинает заново с ним; ответ перечисляет символ на элемент, знак текста — символом его класса с `params: {"text": "j"}` |
| `save` | записывает обработанные символы, включая введённые, как файл ленты |

* После каждого шага сессия посылает `state`: `status` (`paused` или
  `finished` после вердикта), `active` (`states()`), `fired`, `position`,
  `events` (`symbols()`), `output` и, когда прогон его получил, `verdict` с
  `message` в `text`.
* Каждый символ — сообщение `history`: символ (`EOF` для конца), знак текста
  в `params`, позиция, источник (`input` или `user`), исход (`fired` или
  `rejected`) и идентификаторы сработавших элементов.
* Начало не даёт строки истории: его отметки и выход приходят с первым
  `state`.
